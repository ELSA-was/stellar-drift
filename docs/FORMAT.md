# 节点数据格式规范（FORMAT.md）——每个写手代理必须严格遵守

## 文件与结构
- 每章一个文件：`data/chNN.js`（NN两位数，01-42）。
- 文件结构（注意：直接 push 到 window.STORY，末尾必须有分号）：

```js
// 第N章 标题 —— 作者批次X
window.STORY.push({
  id: "ch01",
  title: "第一章 · 初评级",
  phase: "选秀",        // "选秀" | "团综" | "结局"
  week: 1,             // 选秀期1-12；团综期填 13+(团综周序)；结局填 null
  nodes: [ /* 节点数组 */ ]
});
```

## 节点类型（t 字段，全部小写）

### 1. 背景切换
`{t:"bg", v:"lobby"}` — v 可用值见下方【背景表】。

### 2. 旁白
`{t:"n", x:"旁白文本"}` — 40-160字/条为宜，可连续2-3条。

### 3. 对白
`{t:"d", who:"苏景行", x:"台词", fx:"smile"}` — fx 是表情标签，可用：neutral, smile, laugh, shy, angry, sad, cry, shock, cool, sleepy, blush。可选字段。

### 4. 玩家心声（可选，替代部分旁白）
`{t:"m", x:"你的内心活动"}` — 显示为斜体内心独白。

### 5. 选项（每章至少2个）
```js
{t:"choice", prompt:"你要怎么做？", options:[
  {x:"\"现在还早，再练一轮。\"", heart:{苏景行:1, 林墨轩:1}, flag:"extra_training",
   cb:"你拍响手心。苏景行哀嚎一声，还是笑着站起了身。"},
  {x:"\"今天到此为止。\"", heart:{沈时雨:2}, 
   cb:"沈时雨抬起头，眼里有一点没来得及藏好的光。"}
]}
```
- `x`：选项文本。说话写"引号台词"，动作直接写。
- `heart`：对象，键为角色名（必须与角色圣经完全一致：林墨轩/温以恒/顾知遥/沈时雨/苏景行/陆清越/江慕白），值为整数（-3~+5）。
- `flag`：可选字符串，设置全局旗标（小写下划线）。
- `cb`：回调文本（即选择的即时回响，1-2句，作为下一节点前的铺垫）。**必填**。

### 6. 心动提示（节点层也可直接给）
`{t:"heart", who:"沈时雨", delta:2}` — 触发右上角 toast"沈时雨 心动+2"。

### 7. 弹幕（直播场景）
`{t:"danmaku", items:["苏苏的小甜饼🍪|哇这个舞台绝了", "队长冲鸭🚀|注意休息啊", ...]}` — **固定7条**，格式"用户名|内容"。

### 8. 热搜
`{t:"weibo", items:["#星途临时队长是谁# 2.3亿", ...]}` — 4-8条。

### 9. 手机消息（聊天界面）
```js
{t:"phone", who:"苏景行", msgs:[
  {f:"them", x:"小队长，还没睡？", time:"23:41"},
  {f:"me",   x:"在改流程表。"},
  {f:"them", x:"[语音] 3″", time:"23:42"}
]}
```
- f: "them"|"me"。

### 10. 日记
`{t:"diary", who:"沈时雨", date:"第1周 周四 晴", x:"日记正文150-300字"}` — 第一人称。

### 11. 系统公告（评级/排名/任务发布）
`{t:"sys", x:"【节目组】首次顺位发布将于周日晚8点直播进行。"}`

### 12. 章节结束（每个文件最后一个节点）
`{t:"end"}`

## 硬性规则
1. 纯文本，字符串内**禁止出现英文双引号**——中文引号""''正常使用；字符串用英文双引号包裹时内部只能有中文标点。
2. 每章 18-30 个节点，正文总量 2200-2800 字（不含系统文本）。
3. 互动节奏：每 5-8 个节点内必须出现一次 choice 或系统类节点（danmaku/weibo/phone/diary/sys 均算互动），连续纯文节点原则上不超过 10 个。
   - 例外：**群像接力段落**（七人依次登台/依次发言/危机中逐个反应的蒙太奇）允许放宽到 14 个，但该段落前后必须各有一个 choice 或系统类节点夹住。现有 ch01（初评级七人亮相）、ch17（抢答）、ch29（夜潮应急）、ch42（收官谢幕）属此类，是刻意保留的节奏设计。
4. 节点顺序即游玩顺序，引擎线性播放（choice 只影响数值/旗标/回响，不跳章）——这是我们的架构决策：分支体现在数值、回响文本与结局线选择上。
5. 结局章（ch35-42）末尾在 `{t:"end"}` 前加一个 `{t:"verdict", x:"判词文本，可用\n换行"}` 节点。
6. 文件必须能通过 `node --check`（语法校验）。
7. 每章开头 2-3 个节点必须交代时间/空间/情境（衔接上一章结尾，不允许突兀跳转）。
